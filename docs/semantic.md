## 1. 定位与反定位

**定位**：本文定义「web 服务的生命周期由一个进程独占管理，其他进程如何与之交接」的语义——
谁有权杀、谁有权拉、谁有权唤醒，以及**它们之间靠什么互斥**。

**反定位（本文不管什么）**：
- 不管 web 进程内部的插件加载/组合（那是 `preflight` 与 DSH 组合的语义）
- 不管「什么时候该重启」的决策（那是哨兵触发条件 / 爱丽丝的 `daemon_restart` 语义）
- 不管 web 启动后的业务能力（那是各插件的语义）
- **不是**去中心化共识协议——两个进程、单一主机、单一端口，本文只要求「互斥 + 交接 + 兜底」

## 2. 术语表

| 术语 | 含义 |
|------|------|
| **生命周期** | 从「决定重启」到「新 web 就绪并被唤醒」的整个过程（kill → spawn → 等就绪 → 唤醒 → 清理） |
| **owner（持有者）** | 此刻独占生命周期动作权的进程。**同一时刻至多一个** |
| **取租（acquire）** | owner 在动手前写租约，宣告「这段时间归我」 |
| **让位（hold）** | 非 owner 查到租约被他人持有 → **不拉起、不唤醒**，改为收养既有实例 |
| **接管（take over）** | 租约过期后，另一个进程视为空闲并取得动作权 |
| **租约（lease）** | 落盘的一次性所有权凭证：`{owner, atMs, ttlMs, note}` |
| **收养（adopt）** | 不 spawn，改为接管已存在的 web 进程（端口已被占用时） |
| **唤醒（wake）** | 重启完成后向「我的用户会话」投递「请继续」提醒（语义见 SOUL §5.18） |

## 3. 概念模型

```
        ┌────────────── 生命周期（一次重启）──────────────┐
        │                                                │
哨兵 ──取租──► kill 旧 web ──► spawn 新 web ──► 等就绪 ──► 唤醒 ──► 释放租约
（触发式）                                                          │
        │                                                          ▼
守护 ──查租约──► 他人持有？──是──► 让位（不 spawn、不唤醒）+ 证据行  租约过期
（保活式）            │                                            │
                      └──否──► 正常保活：端口空闲则 spawn，占用来则收养 ◄┘
```

不变量（invariants）：
1. **I1 单主人**：任意时刻，生命周期动作权至多属于一个进程。
2. **I2 唤醒唯一**：一次重启**至多**产生一条「web 已重启」唤醒（避免主人收到重复提醒）。〔**2026-09-22 复核补注**：线上 114 个租约周期中 111 个恰 1 条、3 个为 0 条（漏唤醒，另有告警）——故「只产生一条」如实读作「**至多一条**」，见 §6 A8〕
3. **I3 实例唯一**：一次重启后只有一个 web 实例在监听端口（不产生「绑定失败即退出」的残影实例）。
4. **I4 不锁死**：任何 owner 崩溃后，服务必须在有限时间（≤ TTL）内可被另一进程接管。
5. **I5 可追溯**：每次取租/让位/释放/接管都留下人读证据行。

## 4. 契约

### 4.1 租约文件
- 路径：`<DSH_HOME>/.web-lifecycle-lease.json`
- 形状：`{ "owner": "sentinel" | "guardian", "atMs": <epoch ms>, "ttlMs": <ms>, "note"?: string }`
- 默认 TTL：`120_000 ms`（覆盖实测约 24s 的完整周期，含充分余量）
- 写入：**原子**（写 `.tmp` → `rename`），避免读到半截文件
- 释放：不删文件，改写为 `{owner, atMs: 0, ttlMs: 1, note: "released-at-<epoch>"}`——保留「谁在何时放的手」这一证据

### 4.2 裁决（纯函数）
`decideLeaseGate(lease, nowMs, role) → { action: 'proceed' | 'hold', why, holder?, remainingMs? }`

| 输入状态 | 裁决 | 理由串 | 语义依据 |
|---------|------|--------|---------|
| 无租约 | proceed | `no-lease` | I1 空闲 |
| 自己持有 | proceed | `self-held(age=…)` | 自己的周期继续 |
| 他人持有且 age < ttl | **hold** | `held-by-<owner>(age=…,remaining=…,note=…)` | I1/I2/I3 |
| age ≥ ttl | proceed | `lease-expired(age=…>=ttl=…,holder=…)` | I4 兜底 |
| age < 0（时钟偏移） | proceed | `lease-clock-skew(age=…)` | I4：坏数据不得锁死 |
| 文件损坏/空/shape 非法 | proceed | `issue=lease-json-invalid|lease-empty|lease-shape-invalid` | I4：**放行但必须留 issue**（不静默） |

### 4.3 谁在何时调用
| 进程 | 取租 | 查租（让位） | 释放 |
|------|------|-------------|------|
| 哨兵 | 预检通过、即将 `restartWeb` 之前 | —（自己是 owner） | `finally`：`decideAndWake` 与哨兵清理之后 |
| 守护 | —（不主动取租；只在冷启动自愈时充当 owner） | **所有拉起路径之前**（闸门设在 `spawnWeb` 入口：启动自检 / 崩溃自愈 / 心跳保活）+ **唤醒之前**（`notifyWebReady`） | 只释放自己的 |

### 4.4 让位的具体语义
- 让位**只针对「拉起」与「唤醒」两件事**，不改其他行为（健康检查、状态跟踪、告警照常）
- 让位时必须落证据行：`生命周期租约：held-by-sentinel(age=22000ms,remaining=98000ms,note=hot-reload:…) ——收养而非拉起（跳过 spawn）`
- 让位不等待、不重试、不排队——租约的过期本身就是接管时机（避免把「让位」做成第二个调度器）

## 5. 边界与信任

- **能力边界 ≠ 沙箱**：租约是**协作式互斥**，不是强制锁——它防的是「两个自己人重复动手」，不防恶意进程
- **不夺权**：`clearLease(owner)` 只在当前持有者等于自己时才清除；守护不得清哨兵的租约
- **不越界**：租约只管生命周期动作权，不赋予任何额外能力（不能 kill 非 dsh 进程、不能绕过 preflight 门控）
- **preflight 仍是必要条件**：取租发生在预检通过之后——**租约不替代免疫层**，二者顺序不得颠倒
- **失败面**：租约文件写失败（磁盘满/权限）→ 记日志继续（宁可重复动手，不可停在半路）；读失败 → 按空闲放行 + issue

## 8. 实践修订记录

（本模式第三拍：**实践回修语义文档**——写出实现与真实运行暴露的语义错误/缺失）

- **2026-09-12 首次实践（M1 租约）**
  - 语义**被确认**：「让位只针对拉起与唤醒」（实现中发现若让位也停掉健康检查/告警，会掩盖真实故障，故收窄）
  - 语义**被补充**：原文只说「持有则跳过」，实现后补入 **I4 不锁死** 的完整口径——坏数据（损坏/空/时偏）**放行且留 issue**，不是「拒绝服务」
  - 语义**被修正**：原设计想「释放=删文件」，实践中改为**写已释放留痕**（删文件会让「上一次交接发生在何时」永久丢失，而这正是本次事故最缺的证据）
  - 语义**被修正**：原设计守护只查「自动拉起」那一处；写实现时发现守护有**三条**拉起路径（启动自检/崩溃自愈/心跳保活），遂把闸门收敛到 `spawnWeb` 单一入口——**"只改一处"是这类缺陷的典型形态**（与 SOUL §5.15 §7 同源）
  - 教训（写回本模式）：语义文档若只写「谁做什么」而不写「**在哪些调用点**生效」，实现就会漏点——**调用点清单应作为语义文档的一等公民**
